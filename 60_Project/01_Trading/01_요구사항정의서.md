# 요구사항 정의서 (PRD)

## 1. 문서 개요
- **관련 프로젝트:** MyFin (개인 자산 관리 및 자동 매매 시스템)
- **대상 타겟 사용자 (User Personas):**
    - **김재현:** 본인 (시스템 관리자 및 투자 주체). 데이터 기반의 이성적 투자를 원하며, 파이프라인 자동화를 선호하는 개발자.

## 2. 기능적 요구사항 (Functional Requirements)
- **[Req-01] 사용자 인증 및 권한 관리**
    - JWT 기반의 로그인 시스템 구축.
    - 개인용 시스템이지만, 추후 확장 및 보안을 위해 RBAC(Role-Based Access Control) 구조 설계.
    - 금융 데이터 접근 시 2차 인증(OTP 또는 이메일) 필수 적용.
- **[Req-02] 통합 자산 모니터링 (대시보드)**
    - 여러 증권사/은행의 API를 통해 실시간 잔고 및 보유 종목 수집.
    - 총 자산 대비 주식/현금/기타 자산 비중 시각화(Chart.js 또는 D3.js 활용).
    - 일간/주간/월간 자산 변동 추이 그래프 제공.
- **[Req-03] 자동 매매 엔진 (Trading Engine)**
    - 사용자가 정의한 매수/매도 로직(이동평균선, RSI 등) 설정 기능.
    - 백테스팅 모드: 실제 매매 전 과거 데이터를 통한 전략 검증 기능.
    - 실시간 시세 모니터링 및 조건 충족 시 API를 통한 주문 자동 실행.
- **[Req-04] 알림 서비스**
    - 주요 매매 발생 시 Slack 또는 Telegram으로 즉시 알림 전송.
    - 일일 마감 후 수익률 요약 보고서 자동 생성 및 전송 (n8n 활용 가능).

## 3. 비기능적 요구사항 (Non-Functional Requirements)
- **보안 및 컴플라이언스 (Security):**
    - 모든 금융 API Key는 환경변수(`.env`) 또는 별도의 Vault 서버에서 암호화하여 관리.
    - 데이터베이스 내 민감 정보(계좌 번호 등)는 AES-256 암호화 저장.
    - 외부 노출 최소화를 위해 도커 컨테이너 기반의 폐쇄망 또는 VPN 환경 권장.
- **성능 및 확장성 (Performance & Scalability):**
    - 실시간 시세 수집 시 지연 시간(Latency) 최소화 (Websocket 활용 고려).
    - 향후 가상자산이나 부동산 등 자산 클래스 추가가 용이한 모듈형 아키텍처.
- **가용성 및 신뢰성 (Availability):**
    - 24/7 무중단 운영을 위한 Docker 기반 배포 및 자동 재시작 로직.
    - API 호출 실패 시 재시도(Retry) 로직 및 에러 로그 기록.

## 4. 외부 시스템 연동 (Integrations)
- **연동 대상 시스템:**
    - **증권사 API:** 한국투자증권(KISA), 키움증권 등 (REST API 및 Websocket).
    - **은행/카드사:** 오픈뱅킹 API 또는 Scraping 모듈.
    - **알림 채널:** Telegram Bot API 또는 Slack Webhook.
- **데이터 동기화 방식:**
    - 시세 데이터: 실시간 스트리밍 또는 1분 단위 폴링(Polling).
    - 자산 내역: 1일 4회(장 시작 전, 장중 2회, 장 마감 후) 정기 동기화.

## 5. 제약 사항 (Constraints)
- **기술적 제약:**
    - 증권사 API의 초당 호출 제한(Rate Limit) 준수 필요.
    - 초기 버전은 웹 기반 UI로 개발하며, 모바일은 반응형 웹으로 대응.
- **비즈니스/일정 제약:**
    - MVP(최소 기능 제품) 개발 완료 목표: 작성일로부터 3개월 이내.
    - 개인 자본을 활용하므로 알고리즘 오류 시 즉시 중단 가능한 'Kill-Switch' 필수 구현.
