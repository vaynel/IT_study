# 로드밸런싱 (Load Balancing)

## 개념

여러 서버로 **트래픽을 분산**시켜 부하를 균등하게 나누는 기술.
이중화와 함께 사용되어 **가용성 + 성능** 두 가지를 동시에 확보한다.

---

## L4 vs L7 로드밸런서

| 구분 | L4 (Transport) | L7 (Application) |
|------|---------------|-----------------|
| 동작 계층 | TCP/UDP | HTTP/HTTPS |
| 기준 | IP + Port | URL, Header, Cookie |
| 속도 | 빠름 | 상대적으로 느림 |
| 기능 | 단순 분산 | 경로 기반 라우팅 가능 |
| 예시 | AWS NLB, HAProxy(L4 모드) | AWS ALB, Nginx, HAProxy |

---

## 분산 알고리즘

### Round Robin
- 순서대로 돌아가며 분산 (기본값)
- 서버 성능이 동일할 때 적합

```
요청 1 → Server A
요청 2 → Server B
요청 3 → Server C
요청 4 → Server A ...
```

### Least Connection
- **현재 연결 수가 가장 적은** 서버로 전달
- 처리 시간이 다를 때 유리

### IP Hash
- 클라이언트 IP를 해시하여 항상 **같은 서버**로 연결
- 세션 유지(Sticky Session)가 필요할 때 사용

### Weighted Round Robin
- 서버마다 **가중치** 부여 → 성능 차이 있을 때

## Health Check

로드밸런서가 주기적으로 서버 상태를 확인하여 **죽은 서버에는 트래픽을 보내지 않음**.

```yaml
# Nginx upstream 예시
upstream backend {
    server app1:8080;
    server app2:8080;
}

# HAProxy health check 예시
server app1 10.0.0.1:8080 check inter 2s rise 2 fall 3
```

---

## Nginx 로드밸런싱 기본 설정

```nginx
http {
    upstream myapp {
        least_conn;                   # 알고리즘 선택
        server 10.0.0.1:8080;
        server 10.0.0.2:8080;
        server 10.0.0.3:8080 backup; # 평소엔 제외, 장애 시만 투입
    }

    server {
        listen 80;
        location / {
            proxy_pass http://myapp;
        }
    }
}
```

## 세션 처리 문제

로드밸런싱 환경에서 세션이 특정 서버에 저장되면 **다른 서버로 요청이 가면 로그인이 풀리는 문제** 발생.

### 해결 방법
1. **Sticky Session**: 같은 클라이언트를 항상 같은 서버로 (단점: 부하 불균형)
2. **세션 외부 저장**: Redis 등 외부 저장소에 세션 보관 (권장)
3. **JWT 사용**: 무상태(Stateless) 인증으로 서버 의존 제거
