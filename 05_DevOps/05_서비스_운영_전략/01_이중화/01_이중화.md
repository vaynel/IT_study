# 이중화 (Redundancy)

## 개념

단일 장애점(SPOF, Single Point of Failure)을 없애기 위해 동일한 구성 요소를 **2개 이상 운영**하는 전략.

---

## 구성 방식

### Active-Active
- 두 노드가 **동시에 트래픽 처리**
- 장애 시 나머지 노드가 전체 부하 수용
- 리소스 활용도가 높음

```
Client → LB → [Server A] ← 동시 운영
              [Server B]
```

### Active-Standby (Active-Passive)
- 하나만 운영, 나머지는 **대기 상태**
- 장애 시 Standby가 Active로 전환 (Failover)
- 리소스 낭비가 있지만 구성 단순

```
Client → LB → [Server A]  (Active)
              [Server B]  (Standby - 대기)
```

---

## 이중화 적용 대상

| 계층 | 이중화 대상 | 방법 |
|------|------------|------|
| 네트워크 | NIC, 스위치, 라우터 | Bonding, LACP |
| 서버 | WAS, API 서버 | Active-Active + LB |
| DB | Primary-Replica | Replication + 자동 Failover |
| 스토리지 | 디스크, NAS | RAID, 분산 스토리지 |

---

## SPOF (Single Point of Failure)

- 시스템에서 **하나가 죽으면 전체가 죽는 지점**
- 이중화 설계 시 SPOF를 먼저 찾아야 함

### 예시 - SPOF 진단
```
[Client] → [L4 LB] → [WAS x2] → [DB 단일 인스턴스]
                                     ↑
                               여기가 SPOF
```

---

## 관련 지표

- **가용성**: `(가동 시간) / (전체 시간) × 100`
- **99.9% (3-nines)**: 연간 약 8.7시간 다운타임 허용
- **99.99% (4-nines)**: 연간 약 52분 다운타임 허용
